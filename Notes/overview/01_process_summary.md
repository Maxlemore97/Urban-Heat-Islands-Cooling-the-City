# Biomimicry process summary — the operating manual

Source: `Biomimicry process summary.pptx`, 25 slides.
**Running example: "Passive building ventilation / reduce overheating in a small building
without active air conditioning."** That is our challenge with a different boundary, so this
deck can be read almost as a worked solution for method — never for content.

## Deliverables per step (slide 3)

> "Each step should leave **visible evidence** in your project report."

| Step | Required output |
|---|---|
| DEFINE | challenge + system context |
| IDENTIFY | functional diagram + **4–7 KPIs** |
| INTEGRATE | **2–3 relevant Life's Principles** |
| DISCOVER | **≥ 3 biological models** |
| ABSTRACT | mechanisms + abstracted principles |
| BRAINSTORM | multiple solution directions, **≥ 3 combinations** |
| EMULATE | **2 annotated concepts** + Engineering Canvas |
| MEASURE | critical questions + **1–2 checks** + evaluation + **Concept V2** |

Note "**2–3** relevant Life's Principles" — this deck is stricter than the rubric wording.
Our own list carries three primary plus one secondary, which fits.

## The Creating→Evaluating pipeline (slide 22)

```
1 DIVERGE     Crazy 8s              → 8 rough ideas
2 COMBINE     Morphological matrix  → ≥ 3 concept combinations
3 SKETCH      select 2              → Concept A + B, annotated
4 ENGINEER    Engineering Canvas    → canvas for A and B
5 STRESS-TEST critical questions    → calculate · test · benchmark
6 EVALUATE    KPI evaluation        → compare A vs B
7 ITERATE     Final Concept V2      → improve based on evidence
```

> "**Do not jump from biological inspiration directly to the final solution.**"

## Crazy 8s, as demonstrated on passive cooling (slide 12)

The eight the deck generates: central ventilation core · distributed façade channels ·
wind-catcher roof · **night-flush concept** · **evaporative inlet** · shading + ventilation
skin · **thermal-buffer wall** · hybrid.

> **Crazy 8s rule: "Vary the mechanism or architecture — not only the shape."**

Four of those eight overlap our own function set (night flush → F2/F4, evaporative → F6–F8,
thermal buffer → F4, shading skin → F5). Which means: if our Crazy 8s produces this list, we
have reproduced the lecture rather than done the exercise. **Our eight must be driven by our
own biological models and by F9**, which this example does not contain.

## Morphological matrix, as demonstrated (slide 13)

| Function | Option A | Option B | Option C |
|---|---|---|---|
| Limit heat gain | external shading | ventilated skin | reflective surface |
| Drive airflow | buoyancy / stack | wind pressure | temperature-responsive vents |
| Distribute air | central core | façade channels | floor / ceiling network |
| Release heat | roof exhaust | façade outlets | night flushing |
| Buffer heat | thermal mass | phase-change layer | no added storage |

Then three named combinations are read off the matrix (central core / ventilated façade /
adaptive hybrid). **The rows are the functions from scoping** — so our matrix rows should be
F1, F2, F3, F4, F5, F6–F8, F9, F10, and the columns our abstracted biological principles.

## Concept sketch annotation (slide 14)

> "Use the drawings to explain the transfer — **not as proof that the concept works**."

Annotate: ① inlet ② channels ③ driving effect ④ outlet ⑤ heat path ⑥ materials ⑦ key
dimensions ⑧ expected performance. And: **state what is inspired by biology and what is
conventional engineering.**

## Two technically distinct concepts (slide 15)

> "**Do not submit two cosmetic variations.**"

Each concept comes with its own critical question. Their examples: *"is buoyancy sufficient
under realistic temperature differences?"* and *"how sensitive is performance to wind
direction and façade orientation?"*

## Engineering Canvas — the nine fields (slides 16–17)

| Field | Question |
|---|---|
| FUNCTION | what must it achieve? |
| BIOLOGICAL MECHANISM | how does nature achieve it? |
| ABSTRACTED PRINCIPLE | what is the general principle? |
| TECHNICAL PRINCIPLE | what is transferred? |
| ARCHITECTURE | components + interfaces |
| INPUTS / OUTPUTS | material · energy · information |
| REQUIREMENTS / KPIs | how well must it work? |
| ASSUMPTIONS | what are we assuming? |
| UNCERTAINTIES | what could invalidate it? |
| NEXT CHECK | what should we calculate or test? |

> "It exposes gaps and turns a promising sketch into a concept that can be questioned,
> calculated, tested and compared. **Output = critical questions.**"

Chain: **canvas → 2–3 critical engineering questions → 1–2 checks → update the concept
before the KPI comparison.**

## Checks and review (slide 18)

Critical questions are of the form **"What must be true for the concept to work?"** — their
examples: sufficient airflow? enough load capacity? realistic collection area? acceptable
heat transfer? scalable mechanism?

Check types allowed: back-of-the-envelope calculations · simple experiment · material
comparison · order-of-magnitude cost.

> "**AI as reviewer:** ask AI to identify weak assumptions and needed evidence. Then the team
> decides which criticism is relevant and **verifies formulas, units and claims**."

## Evaluation (slides 19–21)

Score with short evidence on: performance/KPIs · technical plausibility · critical
assumptions · Life's Principles · feasibility/testability · circular-economy measures.
**"You do not need all of them."**

> "A strong evaluation includes **limitations and trade-offs** — not only positive claims."

And on Life's Principles specifically: *"Use them critically — not as a checklist of positive
claims. Look for trade-offs: more surface area may improve cooling but increase material
use; adaptive components may improve performance but reduce simplicity and durability."*

That second trade-off is aimed straight at our colour-changing coating option.

Iteration (slide 21): **V1 → review (peer + AI) → evidence (calculation/test) → measure
(KPIs) → V2**, with the required reflection: *what changed? why did it change? which evidence
or feedback informed the change?*

## AI across the process (slide 23)

| Stage | Legitimate AI use |
|---|---|
| Scope | clarify functions, generate alternative problem framings |
| Discover | find biological strategies, explain mechanisms |
| Create | generate technical alternatives, challenge the transfer logic |
| Check | identify assumptions, support calculations |
| Evaluate | act as critical reviewer, generate counterarguments |

> "**Human responsibility: select, verify, calculate, judge, document and explain. AI output
> ≠ evidence.**"

This table is the natural skeleton for our Appendix A.

## Where to search (slides 24–25)

| Purpose | Journals |
|---|---|
| **Discovering** — how does nature do it? | Journal of Experimental Biology · Integrative and Comparative Biology · Nature · PNAS |
| **Case studies** — how have others transferred it? | Bioinspiration & Biomimetics · Biomimetics · Integrative and Comparative Biology |
| **Creating** — how do we implement and test it? | Bioinspiration & Biomimetics · Biomimetics · Advanced Functional Materials · discipline-specific journals |

Recommended path: **AskNature → biology journals (mechanism) → biomimicry journals
(transfer) → engineering journals (implementation and testing)**, with the warning
*"discovery ≠ evidence"* and the instruction to **trace organism → mechanism → abstracted
principle → technical principle**.

> "Tip: search by **FUNCTION + MECHANISM**, not only by organism name."
